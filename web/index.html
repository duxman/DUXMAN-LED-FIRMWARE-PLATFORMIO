Flujo de Uso

¿Cómo se usa DUXMAN LED?

De cero a iluminar en tres pasos comprobables.

01

Compila y Flashea

Usa PlatformIO o el script PowerShell incluido para flashear el binario según tu placa:

pio run -e esp32c3supermini -t upload
→
02

Conecta el Hardware

Alimenta tus tiras LED (5V o 12V con GND común) y conecta la línea de datos al GPIO asignado (por defecto GPIO 8 en C3, GPIO 5 en dev, GPIO 48 en S3).

→
03

Accede a la Web UI

El microcontrolador levanta un punto de acceso Wi-Fi o se une a tu red. Abre su IP en el navegador y contrólalo desde cualquier PC o móvil.

Interoperabilidad

Sincronización en Red & Streaming de Frames

Recepción en tiempo real de protocolos estándar de iluminación y clusters sincronizados.

Streaming Externo con LedFx

DDP & E1.31 / sACN

Capacidad para recibir tramas UDP a alta tasa de refresco enviadas desde herramientas como LedFx o software de control DMX:

  • Protocolo DDP (Distributed Display Protocol): En puerto 4048 UDP, con payload optimizado para microcontroladores.
  • Protocolo E1.31 / sACN: Puerto 5568 UDP con asignación dinámica de universos y canales.
  • Anuncio mDNS: Registro de servicios _ddp._udp y _e131._udp para autodetección inmediata.

Cluster Sync DUXMAN

_duxsync._udp

Sincronización nativa entre múltiples placas DUXMAN LED en la misma red local:

  • Reloj de fase compartido: Efectos sincronizados con exactitud de milisegundos entre lámparas distintas.
  • Rol Maestro / Esclavo: Cambia colores o escenas en un dispositivo y se replicarán en el grupo.
  • Monitoreo de estado: Inspección de telemetría de nodos conectados vía API.

Wiki · General

Visión General & Inicio Rápido

DUXMAN LED Firmware es un firmware modular para ESP32 desarrollado en C++ bajo el framework de Arduino y PlatformIO. Su objetivo es proporcionar control exhaustivo, seguro y de muy alta velocidad sobre tiras LED digitales direccionables sin intermediarios en la nube.

Comandos Básicos de Compilación y Flasheo

PowerShell / PlatformIO CLI
# Compilar para ESP32-C3 Super Mini
pio run -e esp32c3supermini

# Compilar para ESP32 DevKit clásico
pio run -e esp32dev

# Compilar para ESP32-S3
pio run -e esp32s3

# Flashear directamente por puerto USB
pio run -e esp32c3supermini -t upload

# O mediante el script automatizado para Windows
.\tools\flash.ps1 -Profile esp32c3supermini -Action upload -Port COM6

Particionamiento de Memoria

El proyecto utiliza una tabla de particiones huge_app diseñada para microcontroladores con al menos 4MB de memoria flash:

  • App Binaria: ~3.0 MB asignados para albergar el stack completo de red, audio FFT y motores de render.
  • LittleFS: ~960 KB dedicados al sistema de archivos donde se alojan las páginas web HTML/CSS/JS y los archivos de configuración JSON.
Wiki · Arquitectura

Arquitectura del Firmware & Servicios

El firmware implementa un diseño asíncrono y desacoplado mediante tareas de FreeRTOS fijadas a los núcleos del procesador:

Tarea Núcleo (Core) Cadencia Responsabilidades
controlTask Core 0 ~10 ms Servidor Web HTTP, API REST, Wi-Fi, audio I2S, persistencia y watchdog.
renderTask Core 1 ~16 ms (~62.5 FPS) Motor de efectos (EffectEngine), mezcla cromática, limitador de miliamperios y envío DMA.

Servicios Activos en el Arranque

CoreState: Estado central de runtime y concurrencia segura.
StorageService: Gestión de lectura y escritura en LittleFS.
PersistenceSchedulerService: Escrituras diferidas para salvaguardar la Flash.
ProfileService: Carga y aplicación de configuraciones de hardware en caliente.
UserPaletteService: Almacén de paletas cromáticas creadas por el usuario.
WifiService: Conexión STA y punto de acceso de respaldo (AP).
AudioService: Muestreo I2S y cálculo de FFT por frecuencias en tiempo real.
EffectManager: Selección, secuencias y orquestación del render LED.
SyncService: Stack S1-S6: streaming DDP, E1.31 y cluster.
ApiService: Servidor HTTP y puente de comunicación por puerto Serial.
WatchdogService: Monitoreo de salud de hilos y prevención de bloqueos.

Cadena de Render

EffectManager ──> EffectEngine ──> LedDriver ──> [ NeoPixelBus (DMA/RMT) | FastLED | Digital ]
Wiki · API REST

Referencia de la API REST v1

Base HTTP: /api/v1. Los métodos PATCH y POST se aceptan como equivalentes en todos los endpoints de mutación para facilitar integraciones con clientes domóticos.

Endpoints Principales

Familia Método Ruta Descripción
Estado GET / PATCH /api/v1/state Consulta o modificación de brillo (0..255), color, efecto, velocidad y transiciones.
Configuración GET / PATCH /api/v1/config/{network,gpio,microphone,general} Configuración modular por subsistema.
Config Total GET / POST /api/v1/config/all Exportación o importación íntegra de config.json.
Sincronización GET / PATCH /api/v1/sync/config Habilitar modo receptor LedFx (DDP/E1.31) o nodo cluster.
Perfiles GET / POST /api/v1/profiles/{save,apply,default,delete,clone} Gestión en caliente de perfiles de hardware.
Paletas GET / POST /api/v1/palettes/{apply,save,delete} Gestión de degradados y paletas cromáticas.
Efectos GET / POST /api/v1/effects/sequence/{add,delete} Secuencias automáticas temporizadas.
Sistema GET /api/v1/hardware, /api/v1/openapi.json Telemetría de chips, pines y especificación Swagger/OpenAPI.
Depuración POST / GET /api/v1/debug/log, /api/v1/marcalog Imprime marcas y texto por consola Serial de depuración ([MARCALOG] <texto>).

Ejemplo: Cambiar Estado por HTTP

HTTP Request
PATCH /api/v1/state HTTP/1.1
Content-Type: application/json

  "power": true,

Wiki · GPIO & Hardware

Perfiles GPIO & Limitador de Corriente

Un perfil es una captura íntegra del estado y conexión de pines. Los perfiles permiten conmutar entre diferentes configuraciones físicas de lámparas o tiras en caliente sin necesidad de reiniciar el ESP32:

  • Hasta 4 salidas LED independientes: Cada salida con su propio GPIO, número de LEDs, tipo de integrado (ws2812b, sk6812, ws2815, digital) y orden de color (GRB, RGB, RGBW, etc.).
  • Limitador de potencia activa (Power Management): Calcula el consumo teórico en miliamperios y escala el brillo global automáticamente si se supera el umbral configurado (ej: 2000 mA), protegiendo la fuente de alimentación.
Nota de Seguridad de Hardware: La limitación de corriente por software es una capa de protección adicional; siempre debes asegurar fusibles o cables adecuados a la corriente máxima de tus fuentes de alimentación.
Wiki · Color

Sistema de Paletas Cromáticas

El motor cromático admite tanto paletas integradas de fábrica como paletas creadas libremente por el usuario:

  • Paletas del Sistema (ID positivo): Catálogo fijo clasificado por estilos: warm, cold, neon, pastel, high-contrast y party. Son de sólo lectura.
  • Paletas de Usuario (ID negativo): Creadas interactivamente desde la web UI o vía API (/api/v1/palettes/save). Se guardan de manera permanente en /user-palettes.json en LittleFS.

Wiki · Streaming

Compatibilidad de Sincronización (LedFx & Cluster)

El stack de sincronización (fases S1 a S6) permite recibir streaming de fotogramas directamente por red UDP sin pausas:

Integración / Protocolo Estado Modo Recomendado Detalles Clave
LedFx vía DDP Soportado mode=ledfx_realtime, inputProtocol=ddp Puerto DDP configurable (default 4048 UDP). Máximo rendimiento y menor sobrecarga.
LedFx vía E1.31 / sACN Soportado mode=ledfx_realtime, inputProtocol=e131 Puerto E1.31 fijo: 5568 UDP. Universos y canales asignables.
Cluster DUXMAN LED Soportado mode=cluster_sync (Servidor / Cliente) Sincroniza estado y reloj de fase compartido mediante _duxsync._udp.
Comportamiento en Modo Cliente: Al recibir streaming activo de LedFx o cluster (`role: client` y `connected: true`), el firmware suspende automáticamente el micrófono local y anula cualquier efecto programado en el nodo para evitar interferencias confusas con la música. En modo Servidor/Master (`role: server`), el micrófono y los efectos programados permanecen 100% operativos.

Configuración para LedFx con DDP

PATCH /api/v1/sync/config
{
  "sync": {
    "enabled": true,
    "mode": "ledfx_realtime",
    "role": "client",
    "inputProtocol": "ddp",
    "ddpPort": 4048,
    "sourceTimeoutMs": 1500
  }
}

Wiki · FAQ

Preguntas Frecuentes

¿Qué placas ESP32 están soportadas oficialmente?

El proyecto cuenta con perfiles de compilación dedicados para esp32c3supermini (RISC-V de 1 núcleo), esp32dev (ESP32 clásico Xtensa Dual-Core) y esp32s3 (ESP32-S3 Dual-Core LX7).

¿Cuántas salidas LED independientes puedo controlar?

Puedes configurar hasta 4 salidas LED simultáneas en paralelo en distintos GPIOs, cada una con su cantidad de píxeles, chip controlador y orden de color.

¿Requiere conexión a internet para funcionar?

No. El firmware es 100% autónomo. Si no encuentra una red Wi-Fi configurada, levanta su propio punto de acceso (Access Point) para que puedas conectarte directamente desde tu teléfono u ordenador.

¿Se puede sincronizar con la música del ordenador?

Sí, activando el modo DDP o E1.31 puedes recibir en directo los canales de audio procesados por herramientas como LedFx sin retardo perceptible.

¿Cómo se maneja el desgaste de la memoria Flash?

Mediante el PersistenceSchedulerService, las mutaciones rápidas (como mover un deslizador de brillo) se agrupan en memoria RAM y solo se sincronizan a la memoria Flash tras un periodo de inactividad, evitando escrituras reiteradas.
